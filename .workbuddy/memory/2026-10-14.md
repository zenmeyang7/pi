## rerank 性能排查 + 切 GPU 推理

- **根因**：reranker.py 写死 `providers=["CPUExecutionProvider"]`（rag/reranker.py 旧 92-93 行），本机有 RTX 4050 Laptop 6GB 但没用上。模型是 xlm-roberta-base（12 层/768 维/FP32/1.1GB ONNX），CPU 上每 query 重排（RECALL_K=20 docs）约 1-2s，全量 eval 196 次约 5 分钟。
- **CUDA 路线失败**：onnxruntime-gpu 1.31 的 wheel 不带 cuBLAS（cublasLt64_13.dll）和 cuDNN 9，CUDAExecutionProvider 在 InferenceSession 初始化时静默 fallback 到 CPU（`get_providers()` 返回 CPUExecutionProvider）。需要额外装 CUDA Toolkit 13 + cuDNN 9（几个 GB），成本过高，用户放弃。
- **最终走 DirectML**：`uv remove onnxruntime-gpu && uv add onnxruntime-directml`（清华镜像，17s 下完）。零额外配置，RTX 4050 上 DmlExecutionProvider 生效，`active_provider=DmlExecutionProvider`。benchmark：20 docs/query，5 次 p50=376ms（vs CPU 1-2s），加速约 3-5 倍，196 次重排从 ~5min 降到 ~75s。
- **代码改动**：
  - rag/config.py：加 `RERANK_PROVIDER`(auto/cuda/dml/cpu) + `RERANK_BATCH`(默认 16) 配置项
  - rag/reranker.py：加 `_resolve_providers()`，providers 改成 auto 优先 `cuda→dml→cpu`；`BATCH` 改实例级从 config 读（`self.batch`）；记录 `active_provider` 便于排查 fallback
  - .env：加 `RAG_RERANK_BACKEND=onnx`（跳过 auto 模式的 llama-server 5s 探活超时）+ `RAG_RERANK_PROVIDER=auto`
- **踩坑**：uv add onnxruntime-gpu 走默认 PyPI 卡 30 分钟无输出（SIGTERM），换 `UV_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple` 后 17s 完成。后续装包默认带镜像。
